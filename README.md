## “小鸡vps”的便宜从哪来

NAT 小鸡的架构很直接：一台物理服务器上切出十几到几十台虚拟机，共用一个公网 IPv4，靠端口映射区分谁是谁。公寓楼共用一个门牌号，每户分到几个房间号，这个比喻基本准确。

由此带来三个硬限制。一般只给 20 个左右 IPv4 端口，SSH 占掉一个还剩 19 个；80 和 443 这类标准 Web 端口开不了，分到的大多是 30000 以上的高位段；共享 IP 一旦被墙，整台母机上的用户一起失联。IPv6 通常是完整 /64 段，端口全开，算是隐藏通道，前提是本地网络支持 IPv6。

成本就是这么压下来的：IP 的钱被几十个人分摊，年付三五块人民币的机器在市场上并不少见。

## SSH 连不上、服务访问不到，问题出在哪

买 NAT 小鸡的人第一周最容易卡在三件事上。

**SSH 必须带商家给的转发端口。** 普通 VPS 直接 `ssh root@IP` 就行，NAT 小鸡不行。商家会把一个公网端口映射到内网 22，比如公网端口是 30101，命令就得写成 `ssh root@公网IPv4 -p 30101`。端口在控制面板的“NAT 管理”页查，每个人不一样，开通后第一件事就是把它抄下来。

**服务必须监听 `0.0.0.0`，不能是 `127.0.0.1`。** 很多人装完 Nginx 默认监听回环地址，外部怎么访问都是拒绝。改成 `0.0.0.0` 或具体内网 IP，再从外部用 `公网IPv4:30102` 这种格式访问。走 IPv6 时反过来，要监听 `[::]` 而不是 `0.0.0.0`，否则 v6 流量进不来。

**面板端口和订阅端口都要单独加映射。** 前面那则实测里踩的坑很典型：3XUI 面板内部默认端口 2053，要在商家面板加一条 2053→2053 的转发；建完入站后订阅更新失败，查下来是订阅地址用了 2096 端口，而商家面板里根本没做 2096 的转发，补上之后恢复正常。有些商家只允许转发 2 万以上的端口，那内部端口也得跟着改。同一个商家不同机器的映射规则都可能不一样，别照抄别人的端口号。

遇到 `Connection Refused`，按这个顺序查：`netstat -tunlp | grep 端口` 确认服务在监听；查 ufw 或 iptables 有没有放行；确认绑定地址不是 `127.0.0.1`；核对公网端口到内网端口的映射关系；最后从外部用 `telnet` 或 `nc -zv` 测连通性。绝大多数情况是服务没监听对端口。

如果你买的是 JustHost，这一节大部分用不上：没有 NAT 层，就不需要端口映射，SSH 默认 22 直连。但“服务监听地址写错”这个坑照样会踩，尤其是同时开 IPv4 和 IPv6 的时候。
